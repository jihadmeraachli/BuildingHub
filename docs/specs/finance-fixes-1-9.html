Finance — Fixes 1 to 9

Before & after for the first finance batch, with worked examples. Prepared so we align before building. Every change is designed to work in both billing modes.

1 Aug 2026 · for partner review

Post-pay (Arrears)Residents pay what they actually owe. Balance = payments − charges (+ starting balance, − adjustments).
Prepay (Dues)Residents pay a fixed amount each period; the system reconciles it against the real balance.
Owner vs TenantEvery unit has an owner; a leased unit also has a tenant. Several fixes below track money separately for each.
1

“Outstanding” should follow the top time filter

Bug
Now — the problem
On the Finance page the top tabs (Month / Year / All time) update Collected and Billed, but Outstanding ignores them. It only reacts to the separate date filter down in the Book section — so it looks out of sync with the figures right next to it.
After — the fix
Outstanding responds to the same top filter as its neighbours, showing the outstanding position as of the end of the selected period. Change the period once and all four numbers move together.
Example — filter set to “This year”

Collected (year)$14,400$14,400
Billed (year)$18,000$18,000
Outstanding$9,200 (all-time — ignores filter)$3,600 (as of 31 Dec)
2

Home-page balance must include starting balances

Bug
Now — the problem
When a building joins, some units already owe money (or are in credit) from before. We enter that as the unit’s starting balance. The home-page (dashboard) headline ignores it — it only counts charges and payments made inside the app.
After — the fix
The dashboard balance includes every unit’s starting balance — both those who begin owing and those who begin in credit — so the headline matches the real books from day one.

3

Voided payment keeps re-appearing

Bug
Now — the problem
Voiding a payment is inconsistent: it leaves the on-screen list but still shows in the downloaded report; and when a new payment is later added, the voided one re-appears in the list — while the report still carries it.
After — the fix
A voided payment is treated the same everywhere — excluded from the list, from all totals, and from the downloaded report — and it stays excluded. (It’s still kept in the database for audit, just never counted.)
Example — void payment of $200, then add a new $150 payment

4

One owner and one tenant per unit

Rule
Now — the problem
A unit that already has an owner can be given a second owner; the same for tenants. This corrupts who is responsible for the money.
After — the fix
A unit may have at most one owner and one tenant. Adding a second is blocked with a clear message — you must remove the existing one first. (This is the foundation the owner/tenant money split, fixes 5–9, relies on.)
Example
ActionNowAfter
A101 has owner Sara → add owner Karimallowed (2 owners)blocked: “A101 already has an owner”
A101 has tenant Ali → add tenant Rimaallowed (2 tenants)blocked: remove Ali first
5

Direct an expense to the owner or the tenant (includes fix 7)

Feature
Now — the problem
When recording an expense you can only allocate it to units in general (an “All members” option). There’s no way to say “this one is the tenant’s responsibility.”
After — the fix
The expense form gains one choice: “For units with tenants, apply to: Owner / Tenant.” Units that have only an owner always go to the owner automatically (no prompt). The old “All members” option is removed (fix 7).
Example — $600 water bill, split by shares across 3 units, “apply to Tenant”

A101owner + tenantTenant
A102owner onlyOwner (automatic)
A103owner + tenantTenant
Both modes: in post-pay the charge is recorded on the chosen party’s ledger; in prepay the same choice decides whose dues that cost feeds into.
6

Owner can switch the view: owner-only / tenant-only / combined

Feature
Now — the problem
For a leased unit there’s no way for the owner to see their own numbers apart from the tenant’s — everything is lumped together.
After — the fix
In Finance and the Dashboard, an owner of a leased unit gets a toggle: Owner only · Tenant only · Combined. The tenant, of course, only ever sees the tenant’s own numbers.
Example — owner of A101 opens Finance
ViewShows
Combined (default)owner + tenant together
Owner onlyonly what the owner owes/paid
Tenant onlyonly the tenant’s charges/payments
8

Record a payment as owner’s or tenant’s

Feature
Now — the problem
A payment is recorded against the unit with no way to say whether the owner or the tenant paid — so a leased unit’s two balances can’t be kept straight.
After — the fix
Only when a unit has a tenant, the payment form shows “Paid by: Owner / Tenant.” The payment reduces that party’s balance only. (This is also what lets fix 11 send the receipt to the right person.)
Example — $200 received for A101, “Paid by: Tenant”
LedgerEffect
Tenant balance+$200
Owner balanceunchanged
Receipt / notificationtenant only
Both modes: post-pay reduces the chosen party’s outstanding; prepay records it against that party’s dues for the period.
9

Balances, reports & dues: total row + owner / tenant sub-rows

Feature
Now — the problem
A leased unit shows a single blended balance — you can’t see how much is the owner’s vs the tenant’s.
After — the fix
Everywhere a unit balance appears — the Book, downloaded reports, and Dues — a leased unit shows a total row with two sub-rows: Owner and Tenant. Units with no tenant show a single row (tenant = N/A).
Example — Finance book
UnitBalance
A101 (leased) — total$450 owed
↳ Owner$150 owed
↳ Tenant$300 owed
A102 (owner only)$150 owed · tenant N/A
Both modes: post-pay sub-rows show each party’s outstanding; prepay sub-rows show each party’s amount due and carry-in (this is also fix 14).
